# Encrypted Pastebin

Web-сервис для создания зашифрованных текстовых записей. Пользователь создаёт текстовую запись, она шифруется (AES-256-GCM) и сохраняется на сервере в виде файла. По полученной ссылке авторизованный пользователь может посмотреть расшифрованный текст или скачать его в виде `.txt`-файла.

## Функциональность

1. Регистрация и вход пользователей (сессии, пароли хешируются bcrypt). Регистрацию можно отключить через `REGISTRATION_DISABLED`.
2. Создание текстовой записи: шифруется алгоритмом AES-256-GCM и сохраняется как файл на сервере, возвращается ссылка на запись.
3. Приватность записи: при создании можно пометить запись как приватную. Приватные видны и редактируются только автором.
4. Неприватные записи отображаются в общей ленте всех зарегистрированных пользователей с указанием автора.
5. Редактирование записи: неприватные записи может редактировать любой зарегистрированный пользователь; приватные — только их автор.
6. Переход по ссылке: авторизованный пользователь получает расшифрованный текст в браузере.
7. Скачивание расшифрованного содержимого в виде текстового `.txt`-файла.
8. Список «Мои записи» для текущего пользователя.

## Технологии

- Node.js + Express
- SQLite (`better-sqlite3`) — хранение пользователей и метаданных записей
- `express-session` + `connect-sqlite3` — сессии
- `bcryptjs` — хеширование паролей
- Встроенный `crypto` (Node.js) — шифрование AES-256-GCM

## Установка и запуск

```bash
# 1. Установить зависимости
npm install

# 2. (Опционально) настроить окружение
cp .env.example .env   # если есть шаблон, либо отредактировать .env

# 3. Запустить
npm start
```

По умолчанию сервис доступен на `http://localhost:3000`.

Интерактивная документация API (Swagger UI) — на `http://localhost:3000/api-docs/`.

Для разработки с автоперезапуском:

```bash
npm run dev
```

## Конфигурация (`.env`)

| Переменная           | Описание                                                        | По умолчанию |
|----------------------|-----------------------------------------------------------------|--------------|
| `PORT`               | Порт сервера                                                     | `3000`       |
| `SESSION_SECRET`     | Секрет для подписи сессий (важно задать свой!)                  | `dev-secret` |
| `DATA_DIR`           | Директория данных (БД, ключ шифрования, файлы записей)          | `data`       |
| `ENCRYPTION_KEY`     | Ключ шифрования AES-256 (hex, 32 байта). Если не задан — генерируется и сохраняется в `data/secret.key` | авто |
| `BASE_URL`           | Внешний URL сервиса (если за reverse-proxy)                     | автоопределение |
| `BASE_PATH`          | Базовый путь при работе по под-пути, напр. `/pastebin` (nginx)  | пусто (корень) |
| `REGISTRATION_DISABLED` | Отключить регистрацию новых пользователей (`true`/`false`)   | `false` |

## Запуск через Docker

Проект содержит готовые `Dockerfile` и `docker-compose.yml`. Подробная инструкция — в файле [DOCKER_RUN.md](DOCKER_RUN.md).

```bash
# Сборка и запуск контейнера
docker compose up -d --build
```

Сервис будет доступен на `http://localhost:3000` (порт из `.env`, по умолчанию 3000).

Особенности:

- Данные (БД SQLite, ключ шифрования `secret.key`, файлы зашифрованных записей) хранятся в именованном Docker-томе `pastebin-data` и переживают перезапуски/пересборки.
- Переменные `SESSION_SECRET`, `ENCRYPTION_KEY`, `BASE_URL` и `PORT` подхватываются из файла `.env` рядом с `docker-compose.yml`.
- Для production обязательно задайте свой `SESSION_SECRET` и зафиксированный `ENCRYPTION_KEY` (иначе при удалении тома ключ будет перегенерирован, и старые записи станут недоступны).
- Нативный модуль `better-sqlite3` компилируется внутри образа (многоступенчатая сборка), поэтому образ собирается без Node.js toolchain в рантайме.

Полезные команды:

```bash
docker compose logs -f      # просмотр логов
docker compose down         # остановить (данные сохраняются)
docker compose down -v      # остановить И удалить том с данными (внимание!)
docker compose restart      # перезапустить
```

## Работа за reverse-proxy / nginx по под-пути

Сервис умеет работать по ссылке вида `https://хост/<путь>/` (например `/pastebin`).

**Базовый путь определяется автоматически** (сервером из URL запроса), поэтому:
- если nginx **срезает** префикс (`proxy_pass http://127.0.0.1:3000/;` с завершающим слешем) — дополнительная настройка **не требуется**;
- если nginx **не срезает** префикс (передаёт под-путь на бэкенд, `proxy_pass http://127.0.0.1:3000;` без завершающего слеша) — тоже **настройка не требуется**: префикс распознаётся автоматически. При желании его можно зафиксировать явно:

```bash
BASE_PATH=/pastebin
```

В обоих случаях все ссылки (статичные ресурсы, API-запросы, страницы `/p/:slug`, Swagger `/api-docs`) автоматически получают нужный префикс. За reverse-proxy также рекомендуется `proxy_set_header Host $host;` и `proxy_set_header X-Forwarded-Proto $scheme;` (приложение учитывает это через `trust proxy`).

## API

Интерактивная спецификация API доступна через **Swagger UI** на `/api-docs/`.

| Метод | Путь                              | Описание                                  |
|-------|-----------------------------------|-------------------------------------------|
| POST  | `/api/auth/register`              | Регистрация `{username, password}`        |
| POST  | `/api/auth/login`                 | Вход `{username, password}`               |
| GET   | `/api/auth/me`                    | Текущий пользователь                      |
| POST  | `/api/auth/logout`                | Выход                                     |
| POST  | `/api/pastes`                     | Создать запись `{content, title?, private?, public_download?}` |
| GET   | `/api/pastes`                     | Лента публичных (неприватных) записей всех пользователей |
| PUT   | `/api/pastes/:slug`               | Редактировать запись `{content, title?, private?, public_download?}` (неприватные — любой авторизованный, приватные — только автор) |
| DELETE| `/api/pastes/:slug`               | Удалить запись (только автор записи)     |
| GET   | `/api/pastes/mine`                | Список записей текущего пользователя      |
| GET   | `/api/pastes/:slug`               | Расшифрованный текст записи (+ автор и признаки `private`, `public_download`) |
| GET   | `/api/pastes/:slug/download`      | Скачать расшифрованный текст как `.txt`. Для записей с включённым параметром `public_download: true` — доступно без авторизации по прямой ссылке |

> Все операции с записями доступны только авторизованным пользователям. Приватные записи (параметр `private: true`) видны, редактируются и скачиваются только их автором; остальные могут их редактировать. Неприватные записи показываются в общей ленте с отметкой автора.
>
> **Скачивание без авторизации:** при создании или редактировании записи можно установить параметр `public_download: true` — тогда любой пользователь сможет скачать файл записи по прямой ссылке `/api/pastes/:slug/download` без входа в систему. Параметр действует только для неприватных записей. Ссылку показывает интерфейс (в блоке создания и на странице просмотра), менять параметр может только автор записи.
